把文本、参考图像和空间条件都接进生成模型之后，我最想确认的事情是：这些输入究竟有没有改变生成过程？接口接通了，loss 也在下降，仍然可能出现模型主要依赖其中一种条件、忽略其他输入的情况。

我理解条件融合时，会先沿着张量走一遍。条件最初是什么形状，在哪里与生成特征相遇，经过下采样后还剩下什么信息，最终又该用什么实验判断它起了作用。这样看，拼接和 Cross-Attention 才不只是两个可以互换的模块名字。

下面用二维结构生成串起这些问题。载荷和边界只是具体的条件来源，讨论的重点仍是表示、特征融合与消融实验；类似问题也会出现在文本引导的图像生成和空间可控生成中。

## 1. 条件如何参与去噪

```text
空间条件 → 对齐网格与多尺度编码 ──────┐
语义条件 → token 编码与类型信息 ─────┤
时间步 t → 时间编码 ────────────────┤
带噪状态 x_t → 去噪网络 → 噪声预测 → 采样更新 → x_(t-1)
                         ↑ 条件融合                  │
                         └──────── 多步迭代 ─────────┘
最终候选 → 边界、材料用量、连通性与物理性能检查
```

以噪声预测形式的扩散模型为例，训练时对真实样本加入已知噪声，再让网络根据带噪状态、时间步和条件预测噪声。相关基础可参考 [DDPM 原论文](https://arxiv.org/abs/2006.11239)。

条件影响去噪输出，并不意味着所有约束都被严格满足。硬约束可能需要显式参数化、投影或额外验证；这些机制是否适用，要由具体任务决定。
## 2. 先区分空间约束与语义偏好

为了看清不同条件的区别，我先按它们与输出的对应关系分类：

| 条件 | 所表达的含义 | 可考虑的表示 |
|---|---|---|
| 设计域与固定区域 | 哪些位置可用、哪些位置受限制 | 与输出对齐的空间 mask |
| 载荷位置与方向 | 力施加在哪里、沿什么方向 | 位置图与向量分量通道 |
| 材料比例等全局参数 | 整体资源或目标约束 | 归一化标量或条件 token |
| 文本与参考描述 | 形态偏好或高层意图 | 带语义的 token 序列 |

我这样分类的原因是，把所有信息压成同一种向量，会让本来明确的对应关系变成模型需要重新学习的事情。

例如，固定区域的位置本来已经与输出网格对齐。如果只把它编码成一个全局向量，网络还要从这个向量中恢复空间位置。反过来，把一句文本复制到每个像素通道，也没有自然解决词语与局部结构的对应关系。

## 3. 从最简单的特征拼接开始

设当前生成特征为 `B × C × H × W`，空间条件为 `B × K × H × W`。沿通道拼接后得到 `B × (C+K) × H × W`，再交给卷积处理，是一种直接的融合方式。

它尤其适合空间上已经对齐的条件。不过，有两个细节比“拼接还是注意力”更容易先出问题。

首先，数据增强必须一致。如果旋转了结构图，就必须同时旋转载荷位置、方向与边界条件。图像看起来变换正确，并不代表物理语义仍然正确。

其次，条件缩放要符合其含义。类别 mask、连续场和方向向量不应无差别使用同一种插值方法。分辨率变化后，小面积支撑区域还可能消失，需要显式检查。

这些错误会制造相互矛盾的训练样本。增加模型容量通常不能修复它们。

## 4. 沿着张量形状理解 Cross-Attention

当条件是一组 token 时，可以让生成特征作为 Query，让条件特征作为 Key 和 Value：

$$
Q = XW_Q, \qquad K = CW_K, \qquad V = CW_V
$$

$$
\operatorname{Attention}(Q,K,V)
=\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d}}\right)V
$$

这里，`X` 是生成过程中的位置特征，`C` 是条件 token。每个生成位置根据相关性，从条件表示中聚合信息。Latent Diffusion Models 展示了将 cross-attention 用于条件生成的方案；具体背景可以参考 [原论文](https://arxiv.org/abs/2112.10752)。

但这一运算并不知道什么叫“必须满足的边界”。权重很大，不等于约束已经满足；权重很小，也不能单独证明该条件没有作用。判断控制效果仍然要看输出和对照实验。

下面是一个最小融合模块，重点展示张量接口：

```python
import torch
from torch import nn

class ConditionFusion(nn.Module):
    def __init__(self, width=128, heads=4):
        super().__init__()
        self.x_norm = nn.LayerNorm(width)
        self.c_norm = nn.LayerNorm(width)
        self.attn = nn.MultiheadAttention(
            width, heads, batch_first=True
        )

    def forward(self, x, condition, padding_mask=None):
        # x: [B, N, D], condition: [B, M, D]
        # padding_mask: [B, M]，True 表示忽略该条件位置
        c = self.c_norm(condition)
        update, _ = self.attn(
            self.x_norm(x), c, c,
            key_padding_mask=padding_mask,
            need_weights=False,
        )
        return x + update

model = ConditionFusion().eval()
x = torch.randn(2, 64, 128)
c = torch.randn(2, 12, 128)
mask = torch.zeros(2, 12, dtype=torch.bool)
mask[:, -2:] = True
with torch.no_grad():
    y = model(x, c, mask)
assert y.shape == x.shape
```

这不是完整扩散模型：它不包含条件编码器、时间步编码、去噪目标或采样器。位置编码、条件类型编码也需要由上游提供，否则条件序列未必包含我们期望的空间与语义信息。

使用时应保证每个样本至少存在一个有效条件 token，不要把全部位置屏蔽；缺失条件可以设计专门的空条件表示。`key_padding_mask` 的布尔语义和输入形状可以核对 [PyTorch 官方文档](https://docs.pytorch.org/docs/stable/generated/torch.nn.MultiheadAttention.html)。

### 4.1 一组具体的张量规模

假设特征图大小为 `16 × 16`，通道宽度为 128，条件有 12 个 token，使用 4 个注意力头。展平后 Query 输入是 `[B, 256, 128]`，每头的特征维度为 32；注意力分数的逻辑形状为 `[B, 4, 256, 12]`。

若特征图改为 `64 × 64`，位置数从 256 增加到 4096，相同条件长度下分数元素数量增加 16 倍。具体实现可能避免显式存储完整分数矩阵，但不能因此忽略高分辨率融合的计算成本。

这组形状也揭示了表示问题：12 个 token 中，哪些对应文本，哪些对应全局参数？若类型与位置未编码，网络只得到一组向量，并不知道我们赋予它们的角色。

## 5. 全局布局与局部边界如何分工

“在每一层都注入所有条件”很容易实现，但不一定是最有效的设计。

一种值得验证的假设是：粗尺度特征更适合表达整体布局，细尺度特征更适合补充局部边界。因此，可以将全局目标与高层语义放在低分辨率特征中融合，将空间 mask 在多个尺度对齐后输入。

需要注意，粗尺度也可能丢失细小载荷或固定区域；不能因为采用了层级结构，就假设局部条件必然被保留。应该检查条件下采样后的可见性，并比较只在输入层注入、单层注意力和多尺度融合的差异。

对于显式注意力分数矩阵，主要计算规模随生成位置数 `N` 和条件长度 `M` 的乘积增长。增加高分辨率融合层时，也要同时记录显存与运行时间，避免把额外资源带来的收益误认为结构设计的收益。

## 6. 模型真的用上条件了吗

只展示几张好看的样本，很难回答这个问题。更有说服力的验证应主动改变条件，同时控制其他变量。

| 实验 | 固定什么 | 改变什么 | 观察什么 |
|---|---|---|---|
| 条件敏感性 | 同一随机噪声、同一模型 | 载荷或支撑位置 | 结构是否出现符合任务语义的变化 |
| 条件消融 | 数据与训练预算 | 去掉某类输入条件 | 对应约束指标是否退化 |
| 融合方式对照 | 尽量匹配参数量和计算预算 | 拼接、单层、多尺度融合 | 有效性与成本之间的变化 |
| 泛化测试 | 已训练模型 | 未见过的设计域或边界组合 | 控制效果是否仍然成立 |

固定噪声适合做成对比较，但一次比较不足以形成统计结论。应使用多个随机种子和多个条件组合，报告分布，而非只选择最好的样本。

如果训练时从未见过条件缺失，测试时突然遮掉条件，本身就会引入分布偏移。因此，“条件消融”更适合训练相应对照模型，或者明确采用训练过的缺失条件机制。

## 7. 从外观相似走到物理有效

结构生成中的外观相似度，与力学有效性不是同一个指标。可以分别考察材料用量、连通性、边界满足情况，以及在统一物理求解设置下的性能。

这里还需要明确一个评价细节：连通性取决于二值化阈值与邻接定义；物理求解也可能失败。如果只对成功求解的样本报告平均性能，就会隐藏无效样本。至少应同时报告失败率，以及成功样本上的性能统计。

更清楚的实验设计，是把条件融合与物理约束分开比较：无物理约束的基线、改进融合后的模型、加入物理约束后的模型，以及两者结合的模型。这样才能判断收益来自更好地理解条件，还是来自生成后的约束修正。

我会把“接入了条件”和“用好了条件”分成两个阶段。前一个阶段检查张量与坐标，后一个阶段固定其他输入，只改变关心的条件，观察输出有没有按预期变化。只有走完后一步，增加一个融合模块才算有了可以讨论的依据。

同样的条件对齐问题也会出现在程序生成中。我在 [Text-to-CAD 的笔记]({% post_url 2026-11-23-Intent-Aligned-CAD %})里，用参数依赖讨论了怎样把一句需求变成可检查的表示。
